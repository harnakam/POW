# Workflow evidence and execution

All commands emit JSON. Node 20+ is the only runtime dependency; Git supplies optional history evidence. The executable is `../scripts/update.mjs` relative to this reference, also shipped when installing only `update`.

```text
node <skill>/scripts/update.mjs scan --root <repo>
node <skill>/scripts/update.mjs scan --root <repo> --write
node <skill>/scripts/update.mjs plan --root <repo> --timeout-ms 30000
node <skill>/scripts/update.mjs run --root <repo> --workflow package:validate --approve <token> --timeout-ms 30000
```

`scan` without `--write` and `plan` do not create state. A persisted scan is required for execution. `plan` recomputes live inputs instead of trusting state-supplied argv. Approval covers the canonical root, all fingerprinted inputs, workflow and argv, state revision and timeout. Any attempted execution consumes the token, including failures; approval is never stored as a lasting permission. The caller must separately establish that the user authorized the reviewed local step. A token is a freshness/review mechanism, not identity authentication.

## Discovery and inference

The CLI fingerprints repository files without evaluating them. It excludes dependency/output directories (`node_modules`, `dist`, `build`, `coverage`, `.next`, `.venv`, `__pycache__`), `.git`, `.pow`, common credential files and `.env` files. Package declarations produce up to 50 candidate IDs. `.github/workflows/*.yml` and `.yaml` provide literal npm-reference evidence; CI shell is never parsed into executable instructions. Git log supplies file-touch counts from at most 50 commits; no messages, patches, remotes or shell history are stored. HEAD is part of the fingerprint. Missing Git reduces evidence without inventing history.

`historyTouches` counts entry-point changes where available, falling back to package.json changes. It measures recurrence of relevant changes, not execution frequency. Actual executions become independent outcome records. A workflow is `untried`, `observed-success`, `review-failure`, `manual`, or `stale`. Changing evidence invalidates prior applicability while preserving bounded historical outcomes for explanation. A new scan drops removed candidates and recomputes current ones. A failure never trains a new command automatically: review the cause and choose a new plan explicitly.

`sequences` additionally prepares ordered CI job candidates, with each declaration's file and one-based line, a declaration hash and any matching package workflow ID. At most 20 job sequences and 20 declarations per sequence are retained. Supported layout is ordinary two-space job indentation and list/property `run` or `uses` declarations inside `steps`; this is conservative text inspection, not a YAML interpreter. Multiline commands, actions, unmatched shell and publishing stay explicit manual boundaries. Truncated sequences are marked partial. Empty jobs and unsupported YAML shapes provide no sequence rather than invented steps.

A sequence's `basis: inferred-ci-declaration` means its list order was declared within one job, not that any step ran successfully or must run unconditionally. Conditions, matrices, job dependencies, reusable workflows and action behavior remain unresolved; no ordering across jobs is inferred. The plan adds the current local argv and status where a declaration maps to a runnable package candidate, preserving manual boundaries such as build → publish. Sequences are always `executable: false`: review them as reusable preparation, then authorize one local workflow step at a time. A successful local build never grants permission to publish. Source hashes invalidate changed sequences along with individual candidates. Actual outcome records remain separate observations and are not misrepresented as a successful CI sequence.

Runnable candidates must be simple `node relative/file.js|mjs|cjs` declarations, followed only by plain short word arguments or `--check`, `--noEmit`, `--verbose`. Spaces/quotes in script paths, shell operators, Node inline execution/loader flags, `node --test`, package-manager invocations and lifecycle hooks remain manual. Keywords associated with remote/destructive operations also force manual handling. This conservative filter is not a security sandbox: even a script called `check.mjs` can have external effects or access secrets. Review its full behavior and imports, including network calls, before local approval. External/deployment behavior discovered there must be executed separately under explicit authorization, never through this runner.

Direct Node argv is intentional. Windows cannot execute npm.cmd directly with shell:false; invoking npm's JS entry point would still run package scripts through a shell and add lifecycle behavior. This CLI does neither. It uses the current Node executable and passes arguments unchanged on Windows, macOS and Linux. It does not claim equivalence to npm's PATH/environment lifecycle setup. Candidates relying on node_modules/.bin, npm-provided variables or excluded inputs need manual handling. No dependency installation occurs.

## State and limits

`.pow/update/state.json` has schemaVersion 1, canonical-root hash, revision, scan timestamp, full input fingerprint, source path/hash pairs, HEAD, discovery limitations, inferred workflows and ordered sequence candidates with evidence, and observed outcomes. `sequences` is an additive field; an earlier v1 snapshot without it remains readable and is refreshed on the next scan. Source contents, argv, raw process output, credentials and environment values are not persisted. Hashes are change detectors, not anonymization of low-entropy secrets; common secret files are excluded entirely. Paths and workflow names remain metadata: inspect them before sharing state. No source or environment is sent remotely.

Bounds: 2,000 directory entries; depth 12; 1 MiB per file; 32 MiB total input; 50 workflows; 50 Git commits; 50 outcomes retained for at most 90 days on the next written scan; state read limited to 1 MiB. Exceeded fingerprint bounds or encountered symlinks disable execution. Discovery excludes generated/dependency/secret inputs by design: their mutation is outside freshness detection. Plans expire seven days after scan even when hashed inputs match. State versions or root mismatches fail closed; preserve and inspect state rather than silently migrating unknown data.

One invocation performs two fixed read-only Git calls (10-second timeout each) and, for an approved run, one workflow call. Workflow timeout defaults to 30 seconds, hard maximum 60 seconds. Output is limited to 1 MiB and discarded after hashing/counting; a limit breach terminates execution. POSIX uses a process group; Windows uses System32/taskkill.exe for the owned process tree with a bounded fallback. Child-process escape, OS permission failures and malicious scripts cannot be contained by this user-space mechanism; use an OS sandbox where that trust boundary matters. Timeouts bound managed processes, not arbitrary effects already performed.

Writes are serialized by `.pow/update/lock` and use temporary-file rename. State is written before launch with an `interrupted` record, then updated with exit status, duration, output hash/bytes. A crash preserves evidence of an attempted run. If a lock remains after its owner exits, inspect it and remove that file manually; there is no automatic stale-lock takeover. Interrupted or failed outcomes require review and a fresh token. Concurrent repository edits during execution are outside the freshness check: do not edit inputs between planning/approval and launch. State files are owner-only where supported; the repository is otherwise untouched by discovery. Approved scripts retain their own effects and are not rolled back.

When execution fails, JSON distinguishes exit-failure, timeout, output-limit, spawn or interrupted. Inspect source and rerun the command manually under the user's existing authorization if raw diagnostics are required; the store deliberately retains no potentially sensitive output. Do not report metadata-only output as a captured diagnostic transcript. Fix a concrete cause before retrying. Unknown options, malformed state, stale approval, unsafe paths, locks or incomplete scans fail closed with nonzero status. Help is `node <skill>/scripts/update.mjs --help`.
