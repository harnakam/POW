# Executable engineering commands

These four Skills combine agent instructions with standalone, dependency-free Node programs. They do not install an agent framework, inject hooks, make model calls or silently publish. The host agent still investigates and edits the real product. The programs retain bounded evidence, execute authorized commands, and enforce explicit state transitions. Source lives in `commands/<name>/`; installation bundles each directory independently with applicable licenses.

Use `$<name>` in Codex. In a clone, `node scripts/pow.mjs /<name> ...` dispatches arguments directly to the corresponding runtime without a shell. Installer `update` and workflow `/update` are separate actions. Use the installed Skill's absolute script path outside the clone. Read each reference for JSON formats, limits, exit codes and recovery.

| Command | Persistent data | Execution and completion boundary |
| --- | --- | --- |
| [update](../commands/update/SKILL.md) | `.pow/update/state.json`: fingerprints, candidates, CI sequences, revisions, bounded outcomes | Scan is read-only unless `--write`. Fresh single-use plan tokens bind local Node argv and timeout. Shell, npm lifecycle and publication remain manual. |
| [compressor](../commands/compressor/SKILL.md) | External audit/decision JSON; `.pow/compressor/<run>/` verified backups and manifest | Every candidate starts retained. Selected quarantine requires rationale, fresh inventory and explicit protected-file decisions. Restore never overwrites changed files. |
| [hatarake](../commands/hatarake/SKILL.md) | `.pow/hatarake/<run>/`: frozen contract, attempt state, command evidence and reviews | Fixed attempts/time/no-change/failure budgets. Actual artifact content and checks must pass before independent review can approve completion. |
| [design-reasoning](../commands/design-reasoning/SKILL.md) | `.pow/design-reasoning/`: scoped source identity, actual PNGs, critique, comparison HTML | Baseline, bounded changed candidates, real browser interaction, viewport/DOM checks and screenshot-bound visual review. Node 22+ and existing Chromium are needed for capture. |

All state should remain private and ignored. Reports can contain paths, command arguments, source observations, task text or screenshots. These are local trusted-workspace tools, not security sandboxes against adversarial concurrent filesystem manipulation. Review inputs and use disposable authorized data for browser actions. No automatic payment, promotion or commercial agreement is performed.

## Design decisions from research

- [Workflow research](research/2026-10-30-update.md): prefer source-located declarations and observed exit outcomes over an agent's recollection. CI job declaration order is only inferred: conditionals, matrices, action implementations and cross-job dependencies are unresolved. Changed inputs invalidate runnable plans; failures remain evidence rather than triggers for blind retries. Ordered build → publish preparation is inspectable, but whole sequences are not automatically executed.
- [Compression research](research/2026-10-30-compressor.md): unused-reference and similarity signals are review prompts, not deletion proofs. Retain tests unless their required capability has a concrete surviving path and observed verification. Quarantine and conflict-safe restoration provide recovery without pretending line counts measure maintainability.
- [Completion research](research/2026-10-30-hatarake.md): adopt bounded circuit breakers, immutable objectives and explicit continuation signals from the researched approaches. Avoid stdout-only success, self-scoring as proof, infinite loops and forced extra work after success. Checks and artifact predicates can still be poorly specified; external review remains necessary. Hats implementation details could not be verified and are not attributed as adopted code.
- [Design research](research/2026-10-30-design-reasoning.md): combine a deliberate brief, preservation constraints, real before/after captures and external visual judgment. Do not reduce taste to lint or an invented numerical score. Similar project names were distinguished, and license/maintenance observations were recorded. No upstream implementation was copied and no production dependency was added.

The commands interoperate through ordinary paths and evidence, without importing one another. For example, update can identify the existing build command; hatarake can use that reviewed command plus a real artifact predicate; compressor can identify redundant documentation for separate review; design-reasoning can supply actual screen evidence to the reviewer. An update outcome, passing build or screenshot alone never authorizes a deployment or proves the entire objective complete.

## Direct execution evidence — 2026-10-30

Scenarios used disposable workspaces outside this repository. They exercised the shipped runtimes, not a newly generated test suite. They demonstrate these mechanisms on the stated cases; they are not performance benchmarks or evidence of general product correctness.

| Scenario | Observed result |
| --- | --- |
| Workflow failure, change and recovery | A real Node entry exited 7 and its failure was retained. Reusing its token was refused; changing source made the plan stale. Rescan and fresh authorization ran the corrected entry successfully. Environment-file content and raw stdout were absent from persistent state. |
| Ordered CI preparation | A real CI declaration with build followed by publish produced file/line-located sequence steps. Build mapped to direct Node argv; publish stayed manual. Scan/persist/plan exited 0 without executing CI shell. |
| Selected cleanup and recovery | An untracked-file quarantine was refused until its explicit protection decision. Selected bytes were backed up and quarantined. A conflicting restore exited 2 and preserved new work; subsequent restoration reproduced original bytes. Repeated restoration was harmless and stale inventory was refused. |
| Artifact-based completion | A real uppercase converter produced `HELLO WORLD` plus newline. Passing execution entered `review_required`, not complete. Review rejection, fresh verification and approval exercised the completion controls. Those scenario review decisions were control inputs, not independent product-quality judgments. A stdout-only self-claim with missing output artifact stopped after two unchanged attempts. |
| Real UI improvement and critique | Chrome executed task entry and addition on desktop 1280×800 and phone 390×844, before and after responsive/label/hierarchy improvements. The baseline exposed an unnamed input and a phone layout viewport of 1024 despite a 390-pixel capture. Candidate viewport matched 390 with named controls and passing recorded interactions. A separate agent inspected all four PNGs and supplied screenshot-bound critique; the runtime then accepted completion and generated a comparison report. |

Independent adversarial review found and prompted fixes for Git filesystem-monitor hook execution, dirty files hidden by index flags, and iframe responses being mistaken for main-document evidence. Git subprocesses now have a timeout and disable those helpers; nonordinary index flags protect cleanup candidates; browser navigation evidence matches its main frame and loader. Actual phone capture also motivated checking layout viewport width, since screenshot size and overflow alone missed mobile auto-zoom.

A further process-ownership journal failure previously bypassed the normal cleanup path. Hatarake now keeps termination state separate from error text. Direct execution with an intentionally unwritable ownership journal terminated the long-running worker and returned blocked/exit 2 in 338 ms. Syntax checks passed for the installer and all four runtimes; repository validation accepted 20 Skills. All four were installed using the existing ownership-preserving installer, and their installed entry points were executed outside the POW clone (workflow plan, cleanup help, completion status and design status).

The UI review covered captured success states, not full accessibility certification, every route, long content or error behavior. Two identical task rows in the phone capture are consistent with accumulated local data across viewport actions, but the critic could not establish their cause from images alone; the runtime records observations without claiming duplicate insertion is either correct or a product defect. Independent reviewer identity is declared and hash-bound, not cryptographically authenticated. No mechanism can guarantee semantic quality solely from the agent's own contract.

## Operating limits

Do not loop after a successful requested build or execution. Retry only after a relevant change or a concrete new failure within the fixed budget. Do not add tests, snapshots, fixtures or extra harnesses as a finishing ritual. Existing required controls remain intact. Audit findings are not permission to remove files; candidate quality judgments are not authenticated facts; state should not be edited to erase exhausted budgets. Interrupted operations require inspection of their documented locks, processes and retained artifacts before deliberate recovery.
