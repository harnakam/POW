## Actual user problems

- [Ralph issue #340](https://github.com/frankbria/ralph-claude-code/issues/340) reports false stagnation when the working directory is a multi-repository container and subsequent status parsing loses reported progress. The August follow-up includes recorded loop durations and parsed status output. This is a reporter's field observation, not independent reproduction here. POW watches explicit relevant files without requiring a Git repository; those paths must include real task inputs/source.
- [Ralph issue #346](https://github.com/frankbria/ralph-claude-code/issues/346) reports executable project configuration running before trust checks. The issue's October activity includes fixes; do not describe the reported flaw as verified against current main. POW uses strict JSON plus reviewed argv, never sources a repository plan as shell. `shell:false` does not make an explicitly selected interpreter or executable safe.
- [Reddit discussion about the Ralph-Wiggum loop](https://www.reddit.com/r/ClaudeCode/comments/1q9qjk4/the_ralphwiggum_loop/) includes users concerned about usage caps and token consumption, with mixed anecdotal experience. No cost saving conclusion can be drawn. POW records unknown cost/tokens as null, limits actual command attempts/wall time, and refuses to pretend that prompt instructions enforce a dollar cap.
- [Reddit request for continuous execution](https://www.reddit.com/r/ClaudeCode/comments/1r4kdfk/how_to_run_claude_code_contionously_till_the_task/) describes context exhaustion during a requirements-to-review workflow. POW persists objective, contract, execution evidence and remaining bounds for host-agent restart. It does not promise to recover inaccessible conversation context.

These are concrete failure modes, not a prevalence estimate. Public complaints specific to completely, hats, Toryo and Sprag were not verified; absence of retrieved complaints does not establish reliability.

## Chosen implementation

An installed-alone Skill guides the host agent's real implementation. A standard-library Node engine freezes exact reviewed argv, required artifact bytes, watched inputs/source and finite limits. Work commands are optional; the normal host agent does the engineering. No implicit LLM invocation exists. `run` repeats only an explicitly configured worker/transformation; host-managed work returns after one observed attempt. Process exit zero plus output-only completion language cannot satisfy an absent artifact.

Completion has two gates: actual process/artifact evidence, then an explicit independent review bound to the evidence hash and unchanged watched files. The engine records the caller's review attestation; it cannot authenticate a distinct reviewer or judge arbitrary visual/business correctness. Same-user filesystem writes can forge local state, and this is not a sandbox. Contracts whose artifacts are just success receipts must be rejected by the reviewer. Missing meaningful artifact predicates leave this engine unsuitable as an acceptance oracle rather than justifying fake ones.

Each attempt is charged before execution. Wall deadlines include idle/review time; no-change and repeated-failure breakers preserve counters across normal restarts. Crashes retain a lock, attempt count and last launched PID/argv. Recovery requires real process inspection and explicit cleanup acknowledgment; it never deletes a live lock automatically. No auto-commit, rollback, publishing, deployment, generated test files or new verification framework is included.

## Direct execution evidence

`node --check commands/hatarake/scripts/hatarake.mjs` passed. `--help` ran. The first isolated scenario in the sandbox Windows TEMP directory failed before init because rename returned EPERM; no pass is inferred from it. The same finite scenarios were then executed under a writable workspace directory, retaining their JSON contracts and process evidence:

`C:\Project\Agent\pow-hatarake-direct-b03c7f55-8d9e-48ed-a007-67deed3a233c`

Positive objective: read actual `input.txt` (`hello world\n`), transform to uppercase and write actual `output.txt`. Reviewed worker argv used the installed Node executable with `-e` and `fs.readFileSync`/`toUpperCase`/`writeFileSync`; the check independently opened and printed the output. Frozen `exactText` was `HELLO WORLD\n`. Actual run:

```text
node <engine> init <scenario-root>/contract.json <scenario-root>
node <engine> run <run-directory>
node <engine> review <run-directory> <scenario-root>/review.json  # explicit rejection control
node <engine> verify <run-directory>
node <engine> review <run-directory> <scenario-root>/review.json  # explicit approval control
```

Run ID `0d256a20-d991-49ae-bcab-a8e8bbeb0a82`: first execution `review_required`/exit 3; rejection `continue`/exit 3; fresh verification `review_required`; approval `complete`/exit 0; 2 attempts, observed artifact `HELLO WORLD\n`. The review JSONs were scenario controls supplied by the implementer, **not an independent quality assessment** of this feature. Parent review remains necessary. This demonstrates transition handling and actual effects, not general autonomous agent quality.
